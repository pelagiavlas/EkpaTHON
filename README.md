# Study Buddy: ΕΚΠΑthon 2026

> **«Μετράμε πόσο λιγότερο μας χρειάζεσαι.»**

Εφαρμογή μελέτης για φοιτητές με νοητική αναπηρία και μαθησιακές δυσκολίες.

Ο φοιτητής ανεβάζει το PDF του μαθήματος και το βλέπει και το ακούει σε **«Εύκολο στην Ανάγνωση»**. Μετά απαντά σε ερωτήσεις κατανόησης. Όταν κολλάει, παίρνει **υποδείξεις σε 4 σκαλοπάτια** που δεν δίνουν ποτέ έτοιμη την απάντηση. Όσο τα καταφέρνει μόνος, η εφαρμογή **προτείνει λιγότερη βοήθεια** και αποφασίζει ο ίδιος.

Είναι εργαλείο μελέτης και αυτονομίας: όχι θεραπεία, όχι εργαλείο αξιολόγησης για το πανεπιστήμιο. Όλα τα δεδομένα μένουν στη συσκευή του φοιτητή. Δεν αποθηκεύεται διάγνωση.

## Γρήγορη εκκίνηση (για το demo)

Χρειάζεστε Python 3.12 και Node.js 20 ή νεότερο. Σε PowerShell:

```powershell
# 1. Backend
cd backend
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt

# 2. Frontend (μία φορά, και ξανά μετά από κάθε αλλαγή στο frontend)
cd ..\frontend
npm install
npm run build

# 3. Δεδομένα demo: ΣΒΗΝΕΙ ό,τι υπάρχει και βάζει 2 εβδομάδες προσομοιωμένης χρήσης
cd ..\backend
.venv\Scripts\python -m scripts.seed_demo --reset

# 4. Εκκίνηση
.venv\Scripts\python run.py
```

Ανοίξτε το **http://localhost:8000**. Το PDF για το ζωντανό ανέβασμα είναι στο `backend\demo\kefalaio-3-diastima-empistosynis.pdf`.

- Το `run.py` τρέχει πάντα μέσα από τον φάκελο `backend`. Αν τρέξετε απευθείας το `app\main.py`, βγαίνει το σφάλμα `No module named 'app'`.
- **Παλιά βάση από προηγούμενη έκδοση:** τρέξτε το βήμα 3 (`--reset`), γιατί οι πίνακες άλλαξαν.
- **Από κινητό στο ίδιο Wi-Fi:** βάλτε `STUDYBUDDY_HOST=0.0.0.0` στο `backend\.env` και ανοίξτε `http://<IP-του-laptop>:8000`. Η εγκατάσταση ως εφαρμογή (PWA) θέλει HTTPS. Σε localhost δουλεύει και χωρίς.

### Για ανάπτυξη (αλλαγές στο frontend χωρίς build)

```powershell
cd backend;  .venv\Scripts\python run.py        # API στο :8000
cd frontend; npm run dev                         # εφαρμογή στο http://localhost:5173
```

## Σενάριο demo (3 λεπτά)

1. **Τα μαθήματά μου:** «Στατιστική» στο επίπεδο 3 και «Κοινωνική Ψυχολογία» στο επίπεδο 1. Το επίπεδο είναι ανά μάθημα, όχι ανά άνθρωπο.
2. **Στατιστική → Ανέβασε PDF** → διαλέξτε το demo PDF → «Ανέβασε».
3. **«Προτείνουμε να ξεκινήσεις από το επίπεδο 3»:** αυτή είναι η πρόβλεψη. Δείξτε ότι ο φοιτητής μπορεί να διαλέξει άλλο επίπεδο, και αφήστε το 3.
4. **Ενότητα 3.4** → Εύκολο κείμενο. Πατήστε «Άκου»: διαβάζεται φωναχτά και επισημαίνεται το κομμάτι που ακούγεται. Δείξτε το παράδειγμα με τον καφέ, την εικόνα και το «Πρωτότυπο» με ένα πάτημα.
5. **Ερωτήσεις:** «Ρωτάμε περισσότερους ανθρώπους. Τι γίνεται με το διάστημα εμπιστοσύνης;» → **Βοήθεια** (θύμηση του παραδείγματος, «Άκου το παράδειγμα») → **Βοήθεια** («Με 100 φίλους ξέρεις πιο σίγουρα ή λιγότερο σίγουρα;») → γράψτε «μικραίνει» → «Σωστά. Το βρήκες.»
6. **Πρόοδος:** η ένδειξη «Προσομοιωμένα δεδομένα», τα χεράκια ανά εβδομάδα, το γράφημα όπου η βοήθεια πέφτει και οι αλλαγές από επίπεδο 1 σε 2 και σε 3.

Η μπάρα «σήμερα» στο γράφημα δείχνει την πραγματική απάντηση του βήματος 5, με 2 υποδείξεις, γιατί το κεφάλαιο είναι καινούργιο. Αν θέλετε να δείξετε το επίπεδο 1 (2 επιλογές με εικόνες), αλλάξτε το στο βήμα 3.

## Πώς είναι φτιαγμένο

```
backend/                     FastAPI + SQLite (Python)
  app/pdf/                   PDF → κείμενο (pdfplumber) → ενότητες από τους τίτλους
  app/content/
    provider.py              interface ContentProvider: simplify / make_questions / make_hints
    mock.py                  MockProvider: έτοιμο περιεχόμενο από JSON, αλλιώς κανόνες
    rules.py                 απλοποίηση με κανόνες (τύποι και πίνακες μένουν αυτούσιοι)
    llm.py                   LLMProvider: κενή θέση για το LLM αργότερα
    schema.py                Pydantic μοντέλα για ΟΛΟ το «έξυπνο» περιεχόμενο
    data/fixtures/           έτοιμο περιεχόμενο demo (Κεφάλαιο 3 Στατιστικής)
    data/glossary.json       μικρό λεξικό όρων με απλές εξηγήσεις
  app/learning/
    fading.py                κανόνες για τα 4 επίπεδα (μόνο προτάσεις)
    predict.py               από ποιο επίπεδο να ξεκινήσει ένα νέο κεφάλαιο
    answers.py               έλεγχος απαντήσεων χωρίς LLM, μηνύματα
  config.toml                τα νούμερα των κανόνων: αλλάζουν εδώ, όχι στον κώδικα
  scripts/seed_demo.py       2 εβδομάδες προσομοιωμένης χρήσης
  scripts/make_demo_pdf.py   φτιάχνει το demo PDF
frontend/                    React + TypeScript + Vite, PWA
  src/screens/               οι οθόνες
  scripts/make-pictos.mjs    φτιάχνει τα εικονογράμματα (public/pictos)
  scripts/a11y-check.mjs     έλεγχος με axe σε όλη τη ροή
docs/accessibility-checklist.md   τι ελέγχουμε με το χέρι
```

### Τα 4 επίπεδα υποστήριξης (ανά μάθημα)

| Επίπεδο | Τι βλέπει ο φοιτητής |
|---|---|
| 1. Πλήρης βοήθεια | Εύκολο κείμενο με εικόνες και ήχο, ερωτήσεις με 2 επιλογές και εικόνες |
| 2. Καθοδηγούμενη | Εύκολο κείμενο, ερωτήσεις με 3 επιλογές |
| 3. Λιγότερη βοήθεια | Λιγότερες εικόνες, ανοιχτές ερωτήσεις, «Τι σε βοήθησε την προηγούμενη φορά;» |
| 4. Αυτονομία | Ξεκινά από το πρωτότυπο, βοήθεια μόνο όταν τη ζητήσει |

**Κανόνες** (`backend/config.toml`):
- 3 σωστές στη σειρά, με την πρώτη και με 0–1 υποδείξεις → **πρόταση** για λιγότερη βοήθεια.
- 2 από τις 3 τελευταίες λάθος ή με 3+ υποδείξεις → **πρόταση** για περισσότερη βοήθεια.
- Ο φοιτητής εγκρίνει κάθε αλλαγή. Αν πει «Όχι τώρα», η μέτρηση ξεκινά από την αρχή.

**Πρόβλεψη για νέο κεφάλαιο:** για κάθε προηγούμενο κεφάλαιο του μαθήματος, βαθμός = υποδείξεις ανά ερώτηση + 2 × ποσοστό λαθών. Το πιο πρόσφατο κεφάλαιο μετράει διπλάσια από το προηγούμενό του. Ο βαθμός γίνεται επίπεδο με τα όρια του `config.toml`, και η πρόταση ανεβαίνει το πολύ ένα επίπεδο κάθε φορά.

### Η σκάλα υποδείξεων
1. Πού να κοιτάξεις, με κουμπί που ανοίγει την ενότητα ή ξαναπαίζει το παράδειγμα.
2. Μια καθοδηγητική ερώτηση.
3. Δύο επιλογές.
4. Η ίδια έννοια με **άλλο** καθημερινό παράδειγμα. Ποτέ η απάντηση.

Η σωστή απάντηση και η εξήγηση **μένουν στον server**. Η εξήγηση φαίνεται μόνο αφού ο φοιτητής δοκιμάσει να απαντήσει.

## Σύνδεση με LLM αργότερα

Σήμερα **δεν γίνεται καμία κλήση στο internet και δεν υπάρχει API key**. Όλο το περιεχόμενο περνά από το interface `ContentProvider`.

1. Συμπληρώστε τις τρεις μεθόδους στο **`backend/app/content/llm.py`**. Μέσα στο αρχείο υπάρχουν σχόλια για το τι στέλνουμε, πώς ελέγχουμε την απάντηση με Pydantic και τι γίνεται αν είναι άκυρη (μία επανάληψη, μετά σφάλμα).
2. Αντιγράψτε το `backend/.env.example` σε **`backend/.env`** και βάλτε:
   ```
   CONTENT_PROVIDER=llm
   ANTHROPIC_API_KEY=...
   ```
   Το `.env` δεν ανεβαίνει στο git. Το κλειδί μένει μόνο στον backend.
3. Στο LLM πηγαίνει **μόνο το κείμενο της ύλης** και γενικές παράμετροι (επίπεδο, «Εύκολο στην Ανάγνωση»). Ποτέ όνομα, ρυθμίσεις ή διάγνωση.

Χωρίς `CONTENT_PROVIDER` (ή με `mock`) η εφαρμογή δουλεύει όπως τώρα.

**Νέο έτοιμο περιεχόμενο χωρίς LLM:** προσθέστε ένα JSON στο `backend/app/content/data/fixtures/`, με τη μορφή του `statistics_ch3.json`. Οι τίτλοι των ενοτήτων πρέπει να είναι ίδιοι με αυτούς του PDF.

## Έλεγχοι

```powershell
cd backend;  .venv\Scripts\python -m pytest        # 78 tests: PDF, κανόνες επιπέδων, πρόβλεψη, περιεχόμενο, API, demo
cd frontend; npm run a11y                           # axe σε όλη τη ροή (χρειάζεται τον backend με δεδομένα demo)
```

Αποτέλεσμα του `npm run a11y`: **0 προβλήματα σε 88 ελέγχους οθονών** (22 οθόνες × κινητό/laptop × κανονικά/έντονα χρώματα). Ο axe δεν τα πιάνει όλα: η λίστα για τον έλεγχο με το χέρι (NVDA, VoiceOver, TalkBack, zoom, πληκτρολόγιο, γλώσσα) είναι στο [docs/accessibility-checklist.md](docs/accessibility-checklist.md).

**Μετά το `npm run a11y`:** ο έλεγχος απαντά σε ερωτήσεις, οπότε τρέξτε ξανά το `seed_demo --reset` πριν από την παρουσίαση.

## Προσβασιμότητα

- WCAG 2.2 AA, και από το AAA: αντίθεση κειμένου ≥ 7:1, κανένα χρονικό όριο, εξήγηση δύσκολων λέξεων, κουμπιά ≥ 44×44 px.
- W3C COGA: μία ενέργεια ανά οθόνη, «Πίσω» και «Άκου» πάντα στην ίδια θέση, λίγες επιλογές (2–3), κανένα αρνητικό μήνυμα, επιβεβαίωση πριν από σβήσιμο.
- Κάθε πληροφορία με δύο τρόπους (κείμενο + εικονίδιο/εικόνα/ήχος).
- Ρυθμίσεις ως JSON, που εφαρμόζονται με μεταβλητές CSS στο `<html>`. Οι αρχικές τιμές έρχονται από τα `prefers-reduced-motion` και `prefers-contrast`.
- Οι πρώτες ερωτήσεις αφορούν **ανάγκες** («Σε βοηθά να ακούς το κείμενο;»), ποτέ διάγνωση.
- Σελίδα «Δήλωση προσβασιμότητας» μέσα στην εφαρμογή (Ρυθμίσεις).

## Τι δεν κάνει ακόμα

- Σκαναρισμένα PDF (χωρίς OCR): εμφανίζεται το μήνυμα «Αυτό το PDF είναι φωτογραφία, δοκίμασε άλλο».
- Η απλοποίηση με κανόνες (PDF χωρίς fixture) είναι απλή. Γι' αυτό η εφαρμογή το λέει και δείχνει πάντα το πρωτότυπο.
- Οι ανοιχτές απαντήσεις ελέγχονται με λέξεις-κλειδιά. Αν δεν ταιριάξουν, ο φοιτητής συγκρίνει μόνος του με το «τι περιμέναμε».
- Ο σύνδεσμος του υποστηρικτή δουλεύει μόνο όσο τρέχει η εφαρμογή και είναι προσβάσιμη στο δίκτυο.
- Δεν έχει γίνει ακόμα δοκιμή με φοιτητές.
